# VUAG Fantasy Portfolio Tracker

A private, Dockerised simulation of a **£100,000** investment in Vanguard S&P 500 UCITS ETF (USD) Accumulating (**VUAG**, Yahoo symbol `VUAG.L`, ISIN `IE00BFMXXD54`). The opening portfolio is split between a £20,000 Stocks & Shares ISA and an £80,000 General Investment Account (GIA), with UK tax-exposure estimates and a Bed & ISA planner.

This is an educational portfolio dashboard, not a trading platform, broker, financial adviser, tax adviser, or HMRC tax-return calculator.

## Start here

- **New to the tracker?** Read the [complete user guide](docs/USER_GUIDE.md) for first-time setup, a walkthrough of every screen, common workflows, tax terminology, backups, and troubleshooting.
- **Running or developing the project?** Continue with this README for Docker commands, architecture, implementation details, and validation.

## Run with Docker

The only required command is:

```bash
docker compose up -d --build
```

Open [http://localhost:3000](http://localhost:3000). On first use, the app retrieves the VUAG price for the configured start date and shows the price, units, and £20,000/£80,000 allocation before you confirm the opening transactions.

The [user guide](docs/USER_GUIDE.md#first-time-setup) explains what to check before confirming. Initialization locks the acquisition date, price, and units; there is no reset button in the interface.

Useful lifecycle commands:

```bash
docker compose logs -f vuag-portfolio
docker compose down
docker compose down -v   # also deletes the persistent database volume
```

`docker compose down` preserves the explicitly named `vuag-fantasy-portfolio-data` volume. Do not add `-v` if the database should be retained.

## What the application includes

- Portfolio dashboard with total, ISA, and GIA valuations; gain/loss; daily movement; delayed/stale source metadata; and explainable tax exposure.
- Interactive Apache ECharts performance view using real historical `VUAG.L` closes for `1M`, `3M`, `6M`, `YTD`, `1Y`, `3Y`, `5Y`, and `ALL`.
- Complete transaction ledger with opening buys, GIA disposals, ISA acquisitions, Bed & ISA audit groups, ERI adjustments, and tax estimates.
- Bed & ISA preview and apply flow, including the allocated Section 104 cost, gain crystallised, remaining annual exemption, and linked ISA acquisition.
- Tax-year view using the UK 6 April–5 April boundary.
- Manual, source-backed Excess Reportable Income (ERI) records.
- Five-, ten-, fifteen-, and twenty-year scenario projections with explicit forecast labelling.
- Simple and advanced tax profiles plus editable, tax-year-specific rules.
- Light/dark themes, responsive navigation, keyboard-friendly controls, loading states, and explicit error/empty states.

## Architecture

| Layer | Implementation |
| --- | --- |
| UI | Nuxt 4, Vue 3 Composition API, strict TypeScript, Nuxt UI v4, Tailwind |
| Charts | Apache ECharts 6 through `vue-echarts` client components |
| HTTP | Nitro server routes under `server/api` with Zod validation |
| Persistence | SQLite, Drizzle ORM, checked-in SQL migrations, foreign keys, WAL mode |
| Precision | Decimal values stored as SQLite text and calculated with `decimal.js`; units retain 12 decimal places |
| Market data | Replaceable `MarketDataProvider` interface; initial `YahooFinanceProvider` uses `yahoo-finance2` only on the server |
| Business logic | Independent modules for accounting, share pooling, CGT, ERI/income tax, Bed & ISA, and projections |
| Runtime | Multi-stage Docker build running the production Nuxt/Nitro Node server |

Important calculations live outside Vue components. Database table names are singular and migrations are generated by Drizzle.

## Market prices

The normal provider requests `VUAG.L` from Yahoo Finance using the unofficial `yahoo-finance2` package. Yahoo is never called from browser code.

Quote responses contain the current/delayed price, previous close, change, percentage change, market timestamp, available 52-week range, source, and last successful refresh. The server caches successful quotes for 15 minutes by default. If a refresh fails:

1. the app never invents a price;
2. the last successfully cached quote is used, if available;
3. the quote is visibly labelled stale with its last successful update time; and
4. the request fails clearly when neither a provider result nor a cached price exists.

Yahoo Finance access is unofficial and may change or stop working. The provider interface makes a replacement possible without rewriting portfolio accounting or the UI.

A manual GBP price override is available in Settings for testing. When active, it is labelled as a manual price throughout the dashboard.

### Demo fixtures

Set `DEMO_MODE=true` to use deterministic quote and history fixtures without contacting Yahoo. Docker Compose intentionally defaults to `false` so normal operation uses real `VUAG.L` data.

## Opening acquisition

The default start date is 28 August 2026. The setup preview requests the close for that date. When the date is today and no closing value exists yet, a current delayed quote may be used. A verified manual price can be entered when the source cannot supply the date.

After confirmation, the actual acquisition price, gross cost, and fractional units are written to the ledger and holdings. Later market-price changes only revalue those units; they never rewrite the opening acquisition.

## VUAG, cash dividends, and ERI

VUAG is the accumulating share class. Underlying company dividends are reinvested inside the fund, so this fantasy portfolio records:

- **Cash dividends: £0**
- **Excess Reportable Income / reportable income: potentially taxable in the GIA**

The app does not infer ERI from dividend yield and does not silently assume unpublished ERI is zero. Until a record is entered, it displays **Awaiting published ERI data**.

Enter ERI from Vanguard's official offshore-reporting-fund documentation on the Tax page. A record stores the fund, ISIN, reporting period, fund distribution date, amount per unit, currency, source document, verification status, applicable GIA units, and notes. Unverified records remain unapplied. A verified record:

1. calculates non-cash reportable income from the GIA units held at the reporting-period end;
2. contributes to the reportable-income tax estimate for the fund distribution date's tax year; and
3. increases the GIA's allowable CGT base cost by the same amount, avoiding double taxation of income already subjected to income tax.

ERI is never applied to the ISA.

## UK tax model

The initial `2026/27` configuration contains the assumptions in the product brief: £20,000 ISA allowance, £3,000 CGT annual exemption, 18%/24% CGT rates, £500 dividend allowance, 10.75%/35.75%/39.35% dividend rates, £12,570 personal allowance, and £37,700 basic-rate band. An additional-rate threshold is also stored so reportable-income bands can be calculated deterministically.

Rules are editable records, not scattered UI constants. Unconfigured future years reuse the configured baseline only as a visibly labelled **Projection using current tax assumptions**. They are never presented as confirmed future law.

The tax profile supports employment/pension income, other taxable income, other dividends, other capital gains, capital losses, relevant deductions, a personal-allowance override, and ISA allowance used elsewhere. Wider taxable income affects which CGT and dividend-income rates apply.

An unrealised GIA gain is shown as **potential tax exposure**, not tax currently due. CGT is added to crystallised tax only when a disposal transaction exists. ISA gains always contribute £0 of portfolio tax.

## Section 104 and Bed & ISA

The accounting module supports UK share identification in this order:

1. acquisitions on the same day as a disposal;
2. acquisitions in the following 30 days; and
3. the Section 104 pooled holding.

For the normal strategy, an applied Bed & ISA records three linked audit entries:

- a `GIA_SELL` that allocates original pooled cost and cumulative ERI adjustment proportionally, crystallises the gain, and estimates CGT;
- an `ISA_BUY` for the same fantasy value and units as a new sheltered acquisition; and
- a `BED_AND_ISA` summary that does not affect holdings.

The ISA acquisition never enters the GIA share pool. Future transfers shown by the projection are illustrative and are not applied automatically.

## Database persistence, backup, and restore

The container stores SQLite at `/data/vuag.db` in the named `vuag-fantasy-portfolio-data` volume. WAL mode, foreign keys, and a busy timeout are enabled. Migrations run automatically when the server first accesses the database.

For a consistent backup, stop the service first and copy the database from the volume:

```bash
docker compose stop vuag-portfolio
docker run --rm -v vuag-fantasy-portfolio-data:/data -v "$PWD":/backup alpine cp /data/vuag.db /backup/vuag-backup.db
docker compose start vuag-portfolio
```

Restore instructions, including the required warning about replacing the current portfolio, are in [Data storage, backup, and restore](docs/USER_GUIDE.md#data-storage-backup-and-restore). The explicit volume name is stable across Compose project names.

## Local development

Node.js 22 or later is required because the current `yahoo-finance2` release requires it.

```bash
npm install
npm run dev
```

The default local database is `.data/vuag.db`. Copy `.env.example` to `.env` to change database path, market-cache TTL, refresh interval, or fixture mode.

Database commands:

```bash
npm run db:generate
npm run db:migrate
```

After schema changes, inspect the generated SQL in `server/database/migrations` before committing it.

## Limitations

- Yahoo Finance is unofficial, provides delayed data, and may be unavailable or change format.
- Historical charts use available daily closes and do not model dealing spreads, platform charges, tracking difference, or intraday execution slippage.
- The tax engine is an educational estimate. It does not cover every relief, election, anti-avoidance rule, personal-allowance taper detail, residence issue, or HMRC reporting requirement.
- ERI must be entered from official documents and checked for the precise share class, reporting period, currency, and fund distribution date.
- Tax rules and personal circumstances must be checked against current HMRC guidance before any real decision or filing.
- Projections are arithmetic scenarios, not forecasts or investment recommendations.
